BAF_cap: Comprehensive System Architecture & Technical Explanation
===================================================================

1. Introduction & Purpose
-------------------------
BAF_cap is a dual-platform (Android rugged devices & Linux desktop) field data collection and compilation suite specifically engineered for British Columbia’s Vegetation Resources Inventory (VRI) Phase 1 standards. It replaces legacy Windows-based GCap v5.1.1 tools by providing byte-exact `.dat` file compatibility while integrating modern geospatial shapefile rendering (`GPS_MAP`), automated ODS/XLSX reporting, and robust multi-point forestry calculations.

2. Core Architectural Components
----------------------------------
- **`gcap-core` (Pure Kotlin Engine)**: 
  Houses all business logic, data parsers/writers (`DatParser`, `DatWriter`), forestry math (`GcapCalc` supporting both prism BAF variable-radius and fixed-radius sampling), projection utilities (`UtmProj`), and spreadsheet/shapefile format builders (`OdsExporter`, `XlsxExporter`, `ShpFormat`).
- **`app` (Android Module)**:
  Tailored for rugged field hardware (Blackview BV5200 Pro phones and Active 8 Pro tablets). Implements Activities for the MAIN menu, Summary, Tree Entry Grid (`SampleActivity`), Comments, GPS Coordinates, and Settings.
- **`desktop` (Linux Desktop Module)**:
  A native Java Swing desktop application allowing forestry analysts to open, inspect, edit, and summarize ground calls directly on Ubuntu 24.04.

3. Forestry Calculation & Sampling Modes
------------------------------------------
- **Variable-Radius (Prism BAF Mode)**: Uses metric prism BAF (3..30) to evaluate whether borderline trees are IN or OUT based on critical distance formulas (`PRF = 0.5 / sqrt(BAF)`).
- **Fixed-Radius Sampling Mode**: Activated when a valid RADIUS (1.00 to 200.00 m) is entered while BAF is blank. Calculates individual tree basal area ($\pi \times (\text{DBH}/200)^2$), plot area in hectares ($\pi \times \text{RADIUS}^2 / 10000$), point BA/ha, stand density (stems/ha), and species composition weighted by individual basal area proportions.

4. Storage & File Hierarchy
----------------------------
BAF_cap enforces a rigid internal storage structure under `/sdcard/Download/Groundcalls/`:
- **Root (`Groundcalls/`)**: Stores raw `<name>.dat` files and sidecar `<name>.gc.json` metadata.
- **`GPS_MAP/`**: Stores vector shapefiles (`.shp`, `.shx`, `.dbf`, `.prj`, `.cpg`, `.shp.xml`, `.apl`) and map attachments.
- **`XGV_ODS_XLSX/`**: Stores generated individual spreadsheet reports and multi-groundcall batch summaries (`_all_xgv.ods`, `_all_xgvs_for_QA.ods`).

5. Unsolved / Outstanding Technical Problems
--------------------------------------------
Despite successful implementation across almost all requested forestry workflows, the following three issues remain unresolved and require targeted low-level binary inspection or alternative library adoption:

1. **XLSX Exporter Package Corruption**:
   - **Symptom**: Generated `.xlsx` files fail validation when opened in LibreOffice 24.2+ (reporting a file format error or corruption), whereas `.ods` files open perfectly.
   - **Root Cause**: Hand-built OOXML zip packaging (`[Content_Types].xml`, `workbook.xml.rels`, `sharedStrings.xml`, and worksheet part structures) lacks certain strict relationship part mapping or XML namespace declarations mandated by modern Excel/LibreOffice parsers.
   - **Workaround / Next Step**: Since `.ods` export works robustly across all platforms, users can rely on `.ods` for office work, or we can integrate a lightweight mature library like Apache POI or jOpenDocument if native zip generation continues to drop strict OOXML requirements.

2. **Shapefile DBF Attribute Labeling in QGIS**:
   - **Symptom**: Newly created shapefiles (`xgv_all_<crew>.shp`) and edited point shapefiles (`XGV_MP.shp`) correctly display points on the map canvas inside the app, but when loaded into QGIS, the attribute table shows no available values for labeling under the `GCALL_ID` field.
   - **Root Cause**: The binary dBASE Level 7 (`.dbf`) file header, field descriptor array terminator (`0x0D`), and record start byte markers (`0x20`) generated by our custom minimal `ShpFormat.buildDbf` have a byte offset misalignment or string length mismatch that causes QGIS to treat the attribute records as empty or invalid.
   - **Workaround / Next Step**: Rewrite `buildDbf` to match standard DBF header structures byte-for-byte with reference ArcPad DBF templates, or write/read standard dbf libraries.

3. **Tablet Cold-Start & Background Polling Spikes**:
   - **Symptom**: On rugged hardware like the Blackview Active 8 Pro, heavy background storage operations (such as initial folder scanning across dozens of files) occasionally trigger system-level I/O throttling.
   - **Root Cause**: Android's scoped storage SAF and public directory polling over thousands of nested folders can stall if the OS locks media store indices.
   - **Workaround / Next Step**: Implement a cached index manifest for sample files to avoid full disk scans on every app resume.
